# 지폐기(Bill Acceptor) 명령체계 — 연동 참고

USB-OTG 시리얼로 연결되는 지폐기의 명령체계 정리. 카드결제(KICC EasyCardA)의
바이트 프레임(`CMD/GCD/JCD/RCD`)과는 **전혀 다른**, 단순 **ASCII 라인 프로토콜**이다.

> 실제 구현은 프로젝트에 반영돼 있음:
> - 프로토콜 메모: [`SERIALPORT-AND.md`](../SERIALPORT-AND.md) (3. 주의사항 > 지폐기 프로토콜)
> - 프론트 파싱: [`app/composables/useSerial.ts`](../app/composables/useSerial.ts)
> - 테스트 화면: [`app/pages/serial.vue`](../app/pages/serial.vue)
> - 네이티브 transport: [`src-tauri/plugins/tauri-plugin-serial/`](../src-tauri/plugins/tauri-plugin-serial)

---

## 1. 물리 계층 / 연결

| 항목 | 값 |
|---|---|
| 인터페이스 | USB-OTG 시리얼 (WCH / CH340 계열, **vid `0x1A86`**) |
| 통신 속도 | **9600 bps 고정** |
| 라인 종단 | **`\r\n` (CR LF)** |
| 인코딩 | ASCII 텍스트 |

- 에뮬레이터 USB 시리얼 불가 — **실기기 + USB-OTG 필수**.
- `connect()` 자동 선택은 vid `0x1A86` 우선, 없으면 첫 번째 장치. 연결 시 안드로이드
  USB 권한 다이얼로그가 뜬다(거부 시 열리지 않음).
- 한 포트는 **하나의 리더만**. (과거 JS 폴링 좀비 리더가 `BILL:1000` → `ILL:1000`
  바이트 유실을 일으킨 적 있음 → 네이티브 단일 read 스레드로 해결.)

---

## 2. 명령 일람

모든 명령/응답은 `\r\n` 으로 끝난다.

### 2.1 앱 → 지폐기 (요청)

| 명령 | 송신 바이트 | 응답 | 의미 |
|---|---|---|---|
| 투입 개방 | `RUN\r\n`  | `RUN:OK\r\n`  | 지폐 **투입구 개방** — 이 시점부터 지폐 수납 가능 |
| 투입 차폐 | `STOP\r\n` | `STOP:OK\r\n` | 지폐 **투입구 차폐** — 더 이상 수납 안 함 |

### 2.2 지폐기 → 앱 (비동기 푸시)

| 메시지 | 수신 바이트 | 의미 |
|---|---|---|
| 투입 금액 | `BILL:{금액}\r\n` | 지폐 1장이 투입될 때마다 **수시로** 올라옴. `{금액}`은 정수 (예: `BILL:1000`) |

- `BILL`은 요청에 대한 응답이 아니라 **장치가 자발적으로** 보내는 이벤트다.
  `RUN:OK`(개방) 이후 ~ `STOP:OK`(차폐) 사이에 발생한다.
- 금액 합계는 앱이 누적한다(장치는 매 장당 단건만 통보).

---

## 3. 동작 시퀀스 (예시)

```
앱            지폐기
│  RUN\r\n      →               (투입구 개방 요청)
│              ←  RUN:OK\r\n     (개방 확인 → running = true)
│
│   …사용자가 1,000원 투입…
│              ←  BILL:1000\r\n  (합계 1000)
│   …사용자가 5,000원 투입…
│              ←  BILL:5000\r\n  (합계 6000)
│
│  STOP\r\n     →               (투입구 차폐 요청)
│              ←  STOP:OK\r\n    (차폐 확인 → running = false)
```

---

## 4. 파싱 규칙 (현재 구현 기준)

네이티브(Kotlin)가 `\r\n`/`\n` 기준으로 **완성된 라인**을 잘라 `Channel`로 push하고,
JS는 라인 단위로만 처리한다 (JS에서 바이트 버퍼링 없음).

라인 판별 (대소문자 무시):

| 조건 | 처리 |
|---|---|
| `RUN:OK` 포함 | `running = true` (투입 개방 확정) |
| `STOP:OK` 포함 | `running = false` (투입 차폐 확정) |
| `BILL:` 로 시작 | `:` 뒤를 정수 파싱 → 합계 누적. 숫자 아니면 "파싱 실패" 처리 |

송신은 항상 명령 문자열 뒤에 `\r\n`을 붙여 그대로 write:
```ts
await apiWrite(`${command}\r\n`)   // 'RUN' → "RUN\r\n"
```

## 5. UI / 운영 주의

- **STOP 버튼 활성화는 `running`(RUN:OK 수신 여부)이 아니라 "연결 여부" 기준.**
  개방 응답을 못 받은 상태에서도 강제 차폐를 보낼 수 있어야 하기 때문.
- 페이지 언마운트(`onScopeDispose`)·앱 종료(액티비티 `onDestroy`) 시 포트 자동
  disconnect — 좀비 리더 방지.
- 안드로이드 네이티브→JS 이벤트는 **반드시 `Channel`** 로. `addPluginListener` /
  `register_listener` 경로는 권한 자동 등록이 안 돼 막힌다 (자세한 배경은
  [`SERIALPORT-AND.md`](../SERIALPORT-AND.md) 참고).
